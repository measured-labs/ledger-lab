  7. 기반 = payment와 같게: PostgreSQL 16 + JPA + Flyway · repo docs · 브랜치 `feat/adr-000-baseline` · auto · blind/구현 워커 분리 · 송금(Q7) 제외.

- 합의(2026-11-18 사용자 "응 합의, 제안 3가지 넣고 auto로 진행해줘") — 9~11 채택(메인 제안 — payment ADR-000 병합 전 도메인 재리뷰에서 배운 것을 처음부터 넣는다):
  9. 도메인 캡슐화: 엔티티 생성은 팩토리 · 상태 setter는 `protected set` · 리포지토리는 `save` · `find*`만 노출(`delete*` 없음). 일부러 남긴 약점(락 · 버전 · 제약 없음)은 그대로.

## 1. 목표·대상 (필수)

ledger-lab에 ADR-000 베이스라인이 들어간 상태: 도메인(PointWallet · PointEarn · PointUse · PointHistory) · Flyway V1 · API 7종 · 만료 배치 · 기능 테스트가 있고, 로컬에서 정상 경로가 돌며, ADR-000이 "채택"으로 바뀌고 일부러 남긴 약점(§8 표)이 실제로 그 모습으로 드러나는 것을 재현 스모크로 확인한 상태.

## 2. 경계·불변식 (필수)

- 정상 경로(요청이 하나씩 올 때) 불변식: ADR-000 §2.1 ①~⑤ · 사용자마다 잔액 = Σ(ACTIVE이고 만료 전인 적립 건의 `remaining`) + (만료 배치 전 창에서 만료된 적립 건의 `remaining`) · 이력 1행 = 상태 변화 1건 · `balance_after` = 그 변화 뒤 잔액.
- 오류 순서: 입력 검증(400) → 존재(404) → 상태(409 `*_NOT_CANCELABLE`) → 금액(409). 어느 단계에서 거부돼도 상태 불변(롤백).
- 사용 차감: 만료 임박 순(같으면 id 순) · 만료됐으나 배치 전인 건은 사용 대상에서 빠짐 · 깎은 합이 모자라면 409 롤백.
- 만료 배치: 실행 한 번 = 트랜잭션 하나 · 최대 `batch-size`건 · `expiresAt` 순.
- 일부러 깨지게 두는 것(막지 않음): 동시 요청의 잃어버린 갱신 · 동시 첫 적립의 지갑 2개 · 만료 배치 전 창 · 쓴 몫 미회수 · 환원 적립의 새 365일.
- 오류 본문은 언제나 `{code, message}` · 5xx는 고정 문구(원인은 로그) — payment ADR-000과 같은 규칙.

## 5. 검증 방법 (필수)

- blind 테스트 워커: 명세 + ADR-000 + API 계약만 보고 계약 테스트(구현 미열람).
- 구현 테스트 + 전체 `./gradlew cleanTest test` 실패 0.
- red 확인: 핵심 불변식 테스트가 결함을 넣으면 실패하는지 1회 이상.
- 로컬 스모크(임시 postgres:16 · bootJar): 적립 → 사용(여러 적립 건에 걸침) → 부분 사용 취소 → 적립 취소 → 만료 배치 → 잔액 · 이력 · `remaining` record 비교.
- 재현 스모크(Q/A 11): 같은 사용자 동시 사용 · 동시 첫 적립으로 잃어버린 갱신 · 지갑 2개가 실제로 생기는지와 수치.
- 듀얼 리뷰 루프 ≤ 3(Opus 워커 ∥ codex) · 머지 전 안전선.
